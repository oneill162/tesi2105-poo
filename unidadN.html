La cerradura que ya conoce: private

En la Unidad H, la cuenta de la cooperativa guardaba su saldo detrás de private. Compare qué pasa cuando alguien de afuera intenta cambiarlo.

struct CuentaAbierta {
    double saldo = 500.0;
};

CuentaAbierta a;
a.saldo = 1000000;          // nadie lo impide
cout << fixed << setprecision(2) << a.saldo;
1000000.00

Compila y corre. El saldo cambió y nadie se enteró.

No es un ataque sofisticado: es una línea. Si el dato está a la vista, cualquier parte del programa puede dañarlo, a propósito o por error.

class Cuenta {
private:
    double saldo = 500.0;
public:
    double consultarSaldo() const { return saldo; }
};

Cuenta c;
c.saldo = 1000000;          // g++ lo detiene
error: 'double Cuenta::saldo' is private within this context

El programa ni siquiera compila.

La encapsulación es la primera cerradura: el dato solo cambia por las funciones que la clase decide abrir, y esas funciones pueden validar. En esta unidad se añaden las demás.

private, const e invariantes

class Cerradura {
private:
    string pin;          // el secreto
    int intentos = 0;    // invariante: 0 <= intentos <= 3
public:
    explicit Cerradura(const string& p) : pin(p) {}
    bool abrir(const string& intento) {
        if (intentos >= 3) return false;   // bloqueada
        if (intento == pin) { intentos = 0; return true; }
        intentos++;
        return false;
    }
    int intentosFallidos() const { return intentos; }
};

La primera opción en C++.

string administra su propia memoria: no hay tamaño que adivinar. Con getline se lee la línea completa, espacios incluidos.

array<int, 5> casillero = {0, 0, 0, 0, 0};
try {
    casillero.at(2) = 1;       // dentro: bien
    casillero.at(7) = 1;       // fuera: lanza out_of_range
} catch (const out_of_range& e) {
    cout << "Rechazado: " << e.what() << endl;

Rechazado: array::at: __n (which is 7) >= _Nm (which is 5)

Tamaño fijo, pero con guardia.

.at(i) comprueba el índice y lanza out_of_range. Los corchetes [i] no comprueban nada: con 7 escribirían fuera del arreglo sin avisar.

char nombre[8];
snprintf(nombre, sizeof(nombre), "%s", texto.c_str());
cout << nombre << endl;                // corta a 7 + '\0'

char otro[8];
strncpy(otro, texto.c_str(), sizeof(otro) - 1);
otro[sizeof(otro) - 1] = '\0';      // a mano

Bienven Bienven

Si hay que usar char[], siempre con el tamaño.

Las funciones de C que reciben el tamaño cortan en vez de desbordar. strncpy tiene una trampa: si el texto no cabe, no pone el '\0'; hay que ponerlo a mano.

Consulta parametrizada

El ? marca dónde va un dato. La biblioteca de la base de datos envía la orden y los datos por separado (en SQLite, sqlite3_prepare_v2 y sqlite3_bind_text): el apóstrofo de O'Neill es una letra más, nunca parte de la orden.

Lista blanca

Lo que no puede ir en un ? (el nombre de una columna, el sentido de un orden) se escoge de una lista de valores permitidos. Lo que no está en la lista se rechaza.

unique_ptr: un solo dueño, sin delete

    make_unique<Entrada>(Entrada{7, true});
cout << ultima->numero << endl;
unique_ptr<Entrada> nueva = move(ultima);  // pasa el dueno
cout << (ultima == nullptr ? "ultima: vacio"

Y si se intenta tener dos dueños:

unique_ptr<Entrada> copia = ultima;
error: use of deleted function 'std::unique_ptr<_Tp, _Dp>::unique_ptr(const std::unique_ptr<_Tp, _Dp>&) [with _Tp = Entrada; _Dp = std::default_delete<Entrada>]'

RAII

«La adquisición de un recurso es su inicialización»: el objeto que reserva la memoria es el mismo que la libera, en su destructor. Nadie tiene que acordarse del delete, y nadie puede hacerlo dos veces.

Lo que cambió

No hay dos punteros dueños del mismo objeto: copiar no compila, y move pasa la llave y deja el original en nullptr, que se puede comprobar. ASan no encuentra nada en este programa.

Buenas prácticas de codificación segura en POO

La clase como cerradura: valida al nacer, no presta sus llaves y anota lo que pasa sin anotar los secretos.

Un objeto inválido no llega a existir

class Pin {
    string valor;                // private por omision
public:
    explicit Pin(const string& v) {
        if (v.size() < 4 || v.size() > 6)
            throw invalid_argument("de 4 a 6 digitos");
        for (char c : v)
            if (c < '0' || c > '9')
                throw invalid_argument("solo digitos");
        valor = v;      // solo llega aqui si es valido

};

La bitácora es private, pero esta función entrega una referencia a ella: quien la reciba la puede vaciar. Es dejar la puerta cerrada y la llave pegada en la cerradura.

Una fotocopia de la bitácora.

El que la recibe puede hacer lo que quiera con su copia; la original no cambia. Cuesta copiar, así que es para datos pequeños o cuando de verdad se necesita una copia.

La huella (SHA-256 en esta demostración) siempre mide lo mismo, cambia por completo con un dígito y no se puede «deshacer». Al entrar, se calcula la huella de lo tecleado y se compara con la guardada.

Lo que se hace en un sistema real

  • Una sal distinta por usuario, para que dos PIN iguales no den la misma huella.
  • Una función lenta a propósito para contraseñas (Argon2, bcrypt o scrypt), de una biblioteca probada.
  • Nunca un hash ni un cifrado inventado por uno mismo.
  • Con PIN de 4 dígitos hay solo 10 000 posibilidades: la huella sola no basta. Por eso el límite de intentos del Laboratorio N.

Lo que se lleva de esta unidad

Principios

C, I, D. Mínimo privilegio, defensa en profundidad, fallar cerrado, validar toda entrada, no confiar en el cliente, secretos fuera del código.

Memoria

string, .at() y funciones con tamaño contra el desborde; comprobar antes de multiplicar; unique_ptr contra el puntero colgante.

Inyección

El dato nunca se pega a una orden: consultas parametrizadas, listas blancas y nada de system() con datos del usuario.

La clase como cerradura

Valida en el constructor, devuelve const& o copias, no guarda ni muestra secretos y da errores sin pistas. Compile con -Werror y pruebe con los sanitizadores.
