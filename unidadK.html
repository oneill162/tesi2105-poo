Leer por campos con >>

Si el archivo separa los datos con espacios, >> los lee y convierte en una sola condición. Pero un espacio de más lo descuadra todo.

ifstream f("notas.txt");
if (!f.is_open()) return 1;
int numero;
string nombre;
double n1, n2, n3;
cout << fixed << setprecision(2);
while (f >> numero >> nombre >> n1 >> n2 >> n3) {
    cout << numero << " " << nombre << " "
         << (n1 + n2 + n3) / 3 << endl;
}

Que la lectura misma sea la condición

eof() se vuelve true solo después de que una lectura falla. Por eso se pregunta tarde. Con getline el síntoma cambia, pero el error es el mismo.

ifstream f("expediente.txt");
string linea;
int vueltas = 0;
while (!f.eof()) {
    getline(f, linea);
    vueltas++;
    cout << vueltas << ": [" << linea << "]" << endl;
}
1: [numero,nombre,nota1,nota2,nota3] 2: [84231,Ana Rivera,90,85,92] 3: [70112,Luis Ortiz,78,81,70] 4: []

La cuarta vuelta: getline falla, deja linea vacía y el programa procesa una línea que no existe. En el laboratorio sería un estudiante fantasma.

La lectura devuelve el flujo, y el flujo en un while vale false si la lectura falló. Se lee, y solo si salió bien se usa el dato.

while (getline(f, linea)) y while (f >> x): así se lee un archivo completo.

Lo escrito llega al disco al cerrar

ofstream junta lo escrito en un búfer; close() o el destructor (RAII) lo pasan al archivo.

{

Una excepción propia

class ArchivoNoEncontrado : public runtime_error {
public:
    ArchivoNoEncontrado(const string& nombre)
        : runtime_error("no se encontro el archivo "
                        + nombre) {}
};
void abrir(ifstream& f, const string& nombre) {
    f.open(nombre);
    if (!f.is_open())
        throw ArchivoNoEncontrado(nombre);
}
// en main, con nombre leido de cin:
try {
    abrir(f, nombre);
    cout << "Abierto: " << nombre << endl;
} catch (const ArchivoNoEncontrado& e) {
    cout << "Registro: " << e.what() << endl;
}
NO APARECE

Hereda de runtime_error y le pasa el mensaje en la lista de inicialización: what() ya lo tiene. Como también es una exception, la atrapa catch (const exception& e).

«Tipo incompleto» quiere decir que g++ oyó el nombre pero no vio la clase.

Para escribir, ofstream; para las dos cosas, fstream con ios::in | ios::out. Después del error vienen decenas de líneas de «candidate»: lea la primera.

Si lanza de todos modos, no hay catch que valga: el programa termina. Póngalo solo donde de verdad nada puede fallar, como en un destructor.

Lo que se lleva de esta unidad

Abrir y comprobar

ofstream escribe, ifstream lee, fstream hace las dos cosas. Después de abrir, siempre is_open().

Modos

ios::out (el de omisión) vacía el archivo; ios::app añade al final.

Leer

La lectura es la condición: while (getline(f, linea)). Nunca while (!f.eof()). CSV: stringstream y getline con ','.

Cerrar

close() pasa el búfer al disco. Si se olvida, el destructor lo hace al salir del bloque.

try, throw, catch

La excepción baja por la pila, cerrando lo que encuentra, hasta el primer catch que la acepte. Del más específico al más general.

Las suyas

Herede de runtime_error, pásele el mensaje y atrape por referencia: catch (const exception& e).
