Concepto de herencia (simple y múltiple)

Una clase nueva recibe todo lo de otra y le añade lo suyo. Un camión es un vehículo, con ejes.

class Camion : public Vehiculo {
    int ejes;
};

class Derivada : public Base

class Vehiculo {
public:
    string tablilla;
    void describir() const {
        cout << "Vehiculo " << tablilla << endl;
    }
};
class Camion : public Vehiculo {   // Camion es un Vehiculo
public:
    int ejes = 2;
};
int main() {
    Camion c;
    c.tablilla = "TRK-450";   // heredado de Vehiculo
    c.ejes = 3;               // propio de Camion
    c.describir();            // heredado de Vehiculo
    cout << "Ejes: " << c.ejes << endl;

¿Es un o tiene un?

La herencia sirve solo cuando la frase «A es un B» es cierta. Si A tiene un B, B va como miembro. Escoja para cada pareja.

override: que g++ vigile la firma

  

    

    

      
class Vehiculo {
public:
    virtual double tarifa() const { return 1.50; }
};
class Camion : public Vehiculo {
public:
    double tarifa() { return 3.75; }   // sin const
};
int main() {
    Camion c;
    Vehiculo& v = c;
    cout << v.tarifa() << endl;
}

      
warning: 'virtual double Vehiculo::tarifa() const' was hidden [-Woverloaded-virtual=]
note:   by 'double Camion::tarifa()'
$ ./peaje
1.5
Sin const es otra función: no sustituye a la de Vehiculo.
Compila con solo un aviso, y el camión paga $1.50. Es el error más caro: nadie se entera hasta que se revisan las cuentas.

      
class Camion : public Vehiculo {
public:
    double tarifa() override { return 3.75; }
};
El mismo descuido de antes (sin const), ahora con override.

      
error: 'double Camion::tarifa()' marked 'override', but does not override
override le promete a g++ que la función sustituye a una virtual de la base.
Si la firma no coincide (un const de menos, un parámetro distinto, una letra cambiada), ya no compila. El error sale en su pantalla, no en la caseta.

      
class Camion : public Vehiculo {
public:
    double tarifa() const override { return 3.75; }
};
int main() {
    Camion c;
    Vehiculo& v = c;
    cout << v.tarifa() << endl;
}

      
3.75
Misma firma que en la base, más override al final.
virtual va en la base; en la derivada basta override. En el Laboratorio I, cada tarifa() y cada tipo() lo lleva.

Una interfaz: solo virtuales puras

public:

¿Qué se gana con que no se pueda crear un Vehiculo?

  
En la caseta polimórfica, new Vehiculo("ABC-123") pagaba $1.50 sin ser auto ni nada. ¿Qué pasaría si mañana llega una clase nueva que olvida su tarifa?

  

  
Base con tarifa() de $1.50la clase nueva cobra $1.50 sin que nadie lo note
Base con tarifa() = 0¿?

  
Con = 0, una clase que olvida su tarifa no compila. El error aparece al programar, no en la caseta, y nadie crea por accidente un «vehículo» que no es nada.






  
Lo que se lleva de esta unidad

  

    
Herencia
class Camion : public Vehiculo. Solo si «es un» es cierto; si «tiene un», va como miembro.

    
Múltiple
Dos bases a la vez. Si las dos vienen de la misma clase, aparece el diamante; mejor heredar de interfaces.

    
Base y derivada
protected abre a las derivadas. La derivada llama al constructor de la base en la lista. Se arma desde la base; se desarma al revés.

    
virtual y override
Con un puntero o referencia a la base, virtual llama a la función del objeto real. override hace que g++ vigile la firma.

    
Destructor virtual
Si se va a hacer delete con un puntero a la base, el destructor de la base es virtual.

    
Abstractas e interfaces
= 0 hace la clase abstracta: no se crea y obliga a las derivadas. Una interfaz tiene solo funciones = 0.
