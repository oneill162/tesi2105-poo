¿Qué es un lenguaje de programación?

Tema 1 de 9

Un idioma con reglas exactas

Un lenguaje de programación es un idioma artificial para darle instrucciones a una computadora. Igual que el español, tiene palabras (léxico), gramática (sintaxis) y significado (semántica). El compilador lee su código en ese mismo orden.

El español tolera dudas; C++ no

«Nos vemos en el banco.»

¿El banco del parque o el banco donde se deposita? Una persona lo resuelve por el contexto. Si falta una coma, igual entiende.

int edad = 20
cout << edad << endl;
error: expected ',' or ';' before 'cout'

Una computadora no adivina. Cada instrucción tiene un solo significado, y si falta un punto y coma, el programa no se crea.

Historia y evolución

Tema 2 de 9

De la nota de Ada a C++26

Escoja un año. Cada lenguaje resolvió un problema que el anterior dejaba abierto.

La POO nació de una crisis

En 1968, una conferencia de la OTAN en Garmisch, Alemania, le puso nombre al problema: la crisis del software.

Los programas crecían más rápido que la capacidad de entenderlos. Salían tarde, costaban más de lo previsto y fallaban.

AñoRespuesta
1967Simula 67 introduce clases y objetos (Dahl y Nygaard, Noruega)
1970sProgramación estructurada: sin saltos goto, con bloques claros
1972Smalltalk lleva los objetos a todo el lenguaje (Alan Kay)
1985C++ une la velocidad de C con las clases de Simula (Stroustrup)

C++ no se quedó quieto

Un comité de la ISO publica una versión nueva cada tres años. El código de hace veinte años todavía compila, y el lenguaje sigue sumando herramientas.

C++98primer estándar
C++03correcciones

C++14ajustes
C++17el de este curso
C++20módulos, conceptos

En este curso compilamos con g++ -std=c++17, disponible en cualquier compilador actual.

Compilado o interpretado: depende

FormaCuándo traduceEjemplo
CompiladoTodo el programa, antes de correrC++ con g++
InterpretadoInstrucción por instrucción, mientras correPython con CPython
HíbridoA un código intermedio, y luego al vuelo (JIT)Java con la JVM

El mismo código Python corre de dos maneras: CPython, el intérprete oficial, lo ejecuta paso a paso; PyPy lo compila mientras corre y suele ser más rápido.

Por eso, cuando alguien diga «Python es interpretado», la respuesta precisa es: su implementación más usada lo es.

Una variable tiene cuatro cosas: nombre, tipo, dirección en memoria y valor. La dirección será la protagonista de la Unidad E.

Dos trampas que todo programador pisa

División entre enteros

cout << (90 + 85 + 70) / 3;
81

Si los dos lados son enteros, C++ corta los decimales: 245 / 3 da 81.

Decimales que no son exactos

cout << (0.1 + 0.2 == 0.3);
false 0.1 + 0.2 = 0.30000000000000004441

La computadora guarda los decimales en binario y 0.1 no tiene representación exacta. Se compara con una tolerancia:

fabs((0.1 + 0.2) - 0.3) < 1e-9   // true

Tres maneras de equivocarse

  
Toque cada tipo. Los tres programas se compilaron de verdad con g++.

  

    

      
    

    

      
int edad = 20
cout << edad << endl;
e1.cpp:5:5: error: expected ',' or ';' before 'cout'

      
El programa ni siquiera se crea.
g++ señala la línea 5, pero el punto y coma falta en la 4: el compilador se da cuenta en la línea siguiente. Lea siempre la línea anterior.

      
int total = 245, estudiantes = 0;
cout << total / estudiantes;
Floating point exception

      
Compila sin quejas y se cae al correr.
Dividir un entero entre cero detiene el programa. El compilador no podía saber que estudiantes valdría 0.

      
double promedio = n1 + n2 + n3 / 3;
198.333

      
Compila, corre y da un resultado equivocado.
Faltan paréntesis: solo n3 se divide entre 3. Con 90, 85 y 70 el promedio debía ser 81.67. Es el error más peligroso, porque nadie avisa.

Programa y datos en la misma memoria

  

    

      
En 1945, John von Neumann describió la máquina que todavía usamos: el programa se guarda en memoria igual que los datos.

      
La tesis de Church-Turing dice que todo lo que se puede calcular con un procedimiento, lo puede calcular una máquina de Turing. Por eso C++, Python y Java pueden resolver los mismos problemas: cambian la comodidad y la velocidad, no el poder.
