assert detiene el programa si algo es falso

cuenta_test.cpp, con #include <cassert> y la misma Cuenta:

int main() {
    Cuenta a(500.00);
    a.retirar(200);
    assert(a.consultarSaldo() == 300);
    cout << "Prueba 1 bien" << endl;

    Cuenta b(500.00);
    b.retirar(500);
    assert(b.consultarSaldo() == 0);
    cout << "Prueba 2 bien" << endl;
    return 0;
}
$ g++ -std=c++17 -Wall -Wextra -o cuenta_test cuenta_test.cpp $ ./cuenta_test Prueba 1 bien cuenta_test: cuenta_test.cpp:26: int main(): Assertion `b.consultarSaldo() == 0' failed. Aborted

El mensaje dice el programa, el archivo, la línea 26, la función y la condición que resultó falsa. Después, abort() corta el programa: «Prueba 2 bien» nunca sale.

Mensaje de g++ 13.3 con la biblioteca glibc de Linux. Según la terminal, la última línea puede decir Aborted (core dumped).

-DNDEBUG apaga los assert

$ g++ -std=c++17 -Wall -Wextra -o cuenta_test cuenta_test.cpp $ ./cuenta_test Prueba 1 bien cuenta_test: cuenta_test.cpp:26: int main(): Assertion `b.consultarSaldo() == 0' failed. Aborted

Mientras se desarrolla, cada assert está activo.

La falla de retirar con el saldo completo detiene el programa en la línea 26.

$ g++ -std=c++17 -Wall -Wextra -DNDEBUG -o cuenta_test cuenta_test.cpp $ ./cuenta_test Prueba 1 bien Prueba 2 bien

Con -DNDEBUG el compilador borra cada assert.

El mismo programa, con la misma falla, dice «Prueba 2 bien». assert sirve para el programador, no para revisar lo que escribe el usuario.

Cuenta a(500.00);
assert(a.retirar(200));    // la accion va DENTRO
cout << "Saldo: " << a.consultarSaldo() << endl;
$ ./sin_ndebug Saldo: 300 $ ./con_ndebug Saldo: 500

Nunca ponga dentro de un assert algo que el programa necesita hacer.

Con -DNDEBUG desaparece la condición completa, y con ella el retiro. Primero se hace la acción; después se revisa: bool ok = a.retirar(200); assert(ok);

Un mini marco de pruebas en diez líneas

int pasaron = 0, corridas = 0;

void revisar(const string& nombre, bool condicion) {
    corridas++;
    if (condicion) {
        pasaron++;
        cout << "[PASO]  " << nombre << endl;
    } else {
        cout << "[FALLO] " << nombre << endl;
    }
}

A diferencia de assert, revisar no detiene nada: anota la etiqueta y sigue con la próxima prueba.

No. Una prueba que pasa dice que ese caso funciona, nada más. Las pruebas muestran que hay errores; no pueden mostrar que no los hay. Por eso se buscan los límites y los errores, no solo el caso normal.

Técnicas de debugging

La prueba dijo FALLÓ. Ahora se abre el equipo y se sigue el circuito, punto por punto, hasta la falla.

Un mensaje de g++ tiene cinco partes

Falta un punto y coma. Pulse cada parte del mensaje.

int main() {
    double saldo = 500.00
    saldo -= 200;
    cout << saldo << endl;

-Wall -Wextra: los avisos son pistas

Estos programas compilan. Cada aviso señala una línea que muy probablemente está mal.

bool vacia(double saldo) {
    if (saldo = 0) return true;
    return false;
}
avisos.cpp:13:15: warning: suggest parentheses around assignment used as truth value [-Wparentheses] 13 | if (saldo = 0) return true; | ~~~~~~^~~

Un = donde iba ==: asigna 0 al saldo y la condición siempre es falsa.

int contar(const string& s, char c) {
    int k = 0;
    for (int i = 0; i < s.size(); i++)
        if (s[i] == c) k++;
avisos.cpp:19:23: warning: comparison of integer expressions of different signedness: 'int' and 'std::__cxx11::basic_string<char>::size_type' {aka 'long unsigned int'} [-Wsign-compare]

size() no tiene signo y i sí. Aquí no hace daño, pero con un negativo la comparación da al revés. Use size_t i.

char letra(int nota) {
    if (nota >= 90) return 'A';
    if (nota >= 80) return 'B';
}
avisos.cpp:27:1: warning: control reaches end of non-void function [-Wreturn-type] 27 | } | ^

Con una nota de 70 la función termina sin devolver nada: comportamiento indefinido. Falta un return final.

int main() {
    int lecturas[3] = {70, 71, 72};
    int total;
    for (int i = 0; i < 3; i++)
        total += lecturas[i];
$ g++ -std=c++17 -Wall -Wextra -o sinini sinini.cpp $ ./sinini Total: 32979 $ ./sinini Total: 32977
$ g++ -std=c++17 -Wall -Wextra -O2 -o sinini sinini.cpp sinini.cpp:8:15: warning: 'total' is used uninitialized [-Wuninitialized]

Un acumulador sin iniciar: el total cambia en cada corrida. Sin -O2 g++ no avisó; con -O2 analiza más y sí avisa.

Trazas con cerr: puntos de prueba en el código

factura.cpp: el costo de una reparación, con trazas

double subtotal = totalPiezas + manoObra;
cerr << "[TP3] subtotal = " << subtotal << endl;
double pct = 10 / 100;
cerr << "[TP4] pct = " << pct << endl;
double descuento = subtotal * pct;
cerr << "[TP5] descuento = " << descuento << endl;

cerr es la salida de errores: se escribe enseguida, sin esperar, y va por un canal distinto de cout.

$ ./factura [TP1] piezas = 87.50 [TP2] mano de obra = 60.00 [TP3] subtotal = 147.50 [TP4] pct = 0.00 [TP5] descuento = 0.00 ... Total a pagar: $164.46 $ ./factura 2>/dev/null Total a pagar: $164.46

Con 2>/dev/null las trazas se descartan y solo queda lo de cout. La traza TP4 delata la falla: el descuento del 10 % dio 0.

Compile con -g para que gdb conozca las líneas y los nombres:

$ g++ -std=c++17 -Wall -Wextra -g -o lecturas lecturas.cpp $ gdb -q ./lecturas Reading symbols from ./lecturas... (gdb)

Sin -g, gdb corre el programa pero no puede mostrar el código ni las variables por su nombre.

Para salir: quit. En Windows, gdb viene con MinGW; en Linux se instala con sudo apt install gdb.

fuera.cpp leyó fuera del arreglo y aun así imprimió 287. ¿Está bien el programa?

70 + 71 + 72 + 74 = 287. ¿Qué pasa en otra computadora, o con otro compilador?

Síla salida es la correcta
Nofunciona de casualidad
No. Leer fuera del arreglo es comportamiento indefinido: esta vez la casilla de más tenía 0. En otra máquina puede dar otro número o caerse. Que la salida se vea bien no prueba nada; el sanitizador sí lo ve.

El pato de hule: explicar en voz alta

Se le explica el código, línea por línea, a un pato de hule (o a un compañero). Cuando lo que usted dice no coincide con lo que dice el código, apareció la falla.

double subtotal = totalPiezas + manoObra;
double pct = 10 / 100;
double descuento = subtotal * pct;
double base = subtotal - descuento;
Usted: «Le voy a explicar cómo se calcula la factura».

Búsqueda binaria: medir en el medio

La factura sale mal ($164.46 en vez de $148.02). Hay 8 puntos de prueba. Bajo cada punto, en gris, el valor que anotó la bitácora; al medir sale, en color, lo que dio el programa. Mida tocando un punto: si está bien, la falla está después; si está mal, antes.

Mediciones: 0
double pct = 10 / 100;      // int / int da 0
double pct = 10.0 / 100;    // corregida: 0.10

Lo que se lleva de esta unidad

Prueba unitaria

Una pieza sola, con el resultado esperado escrito antes. Casos normales, límite y de error.

assert y revisar

assert detiene el programa y -DNDEBUG lo apaga. Un marco como revisar anota PASO o FALLO y sigue.

Leer antes de cambiar

El primer error de g++ primero; la falla suele estar en esa línea o en la anterior. Cada aviso de -Wall -Wextra es una pista.

Seguir el circuito

Trazas con cerr, gdb con -g, sanitizadores, el pato de hule y la búsqueda binaria.
